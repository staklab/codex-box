# 桌面对话参数同步

模型和思考强度通过桌面现有桥接的 `thread/read` 获取当前配置，不再使用 codex-box 历史预设代替真实状态。菜单显示期间每两秒刷新一次，Windows 编辑期间保留草稿；活动对话变化后重新读取。

macOS 主窗口按 URL 的协议、主机和路径匹配，保留带 `initialRoute` 查询参数的分支窗口。仅调试端口连接失败才重新发现端口，窗口暂时无法识别不会清除健康连接。多窗口通过页面焦点选择目标，并记录最近获得焦点的窗口，供菜单弹出后继续读取。首次连接时若多个窗口都没有焦点记录，提示先点击目标窗口；不会猜测第一个窗口。CDP 请求有独立于页面定时器的原生截止时间，忽略无关事件并匹配请求 ID；页面导航或请求失联后可再次刷新。普通请求最多等待 15 秒，创建分支最多等待 65 秒。

活动路由只从可见编辑器或主内容的已提交 React 祖先读取。隐藏标签页、未提交节点、远程页面和无法唯一确定的页面不会成为写入目标。写入前核对对话 ID；Windows 同时核对编辑开始时的参数，避免覆盖外部变化。`thread/settings/update` 使用 `effort` 字段，写入后再次 `thread/read` 验证模型和思考强度。

当前安装版本的隔离协议测试确认：对已加载会话调用 `thread/resume` 并传入 `config.model_context_window`，会返回成功，但上报窗口不变；单纯重启再恢复已有对话也不能作为窗口生效的保证。

macOS 的上下文菜单支持继承历史创建新分支。界面明确确认后使用官方 `thread/fork` 和窗口配置创建分支，并导航到新对话；原对话、全局默认和其他项目不受影响，无需重启。正在生成或目标已经变化时拒绝创建。分支配置保存为 schema 2，避免使用旧版本未验证的窗口缓存。读取实际窗口时忽略分支创建前继承的用量记录；尚未有新上报时以星号标记所选设置。隔离测试验证设置 123456 后下一轮实际窗口为 117283（保留系统空间），并验证分支继承历史且原对话窗口未变。

首页仍可保存新对话默认窗口。已打开的首页编辑器可能有自己的参数选择，保存默认配置不代表该编辑器即时改变。Windows 也提供继承历史创建上下文分支，保存配置记录并标注预计有效窗口；创建期间继续刷新其他会话。

`thread/read` 不返回服务等级，因此速度模式补读同一活动编辑器的 `serviceTierSettings.serviceTierForRequest`。读取已提交 React Compiler memoCache，必要时读取同一 composer 的工具栏兄弟组件。`priority`/`fast` 显示 Fast，明确的空值显示标准；加载中或缺失值不会被误判为标准。修改速度后再次读取编辑器状态验证。

路由身份仅由页面类型、对话 ID 和主机确定；同一对话组件的速度信息缺失或冲突只影响速度显示。React 祖先、Hook 和依赖链有循环检测及扫描上限。Compiler 缓存逐行扫描，支持超过 100 个槽的缓存行；Hook 链独立遍历，避免被通用对象深度限制截断。

参数栏使用固定列宽。模型、速度与上下文的异步读取完成后一起提交；同一对话的轮询不会先将实际窗口清空为“待上报”，相同数据也不会重复发布。

验证命令：

- `node scripts/test_desktop_thread_route.cjs`：隔离 DOM 中验证隐藏页面、切换、已提交节点和歧义路由。
- `python3 scripts/test_desktop_thread_protocol.py /path/to/codex`：使用临时 `CODEX_HOME` 和本地模拟提供商，验证两对话读取、写入读回、下一轮实际模型/思考参数及桌面同步通知，同时复现已加载窗口无法被 resume 覆盖。不会读取用户配置和凭据。
- Xcode 的 `CodexDesktopThreadSettingsServiceTests`、`CodexThreadContextWindowReaderTests`：参数跟随、目标变化、假成功和模型对应的上下文记录。
- Windows 前端测试和 Rust 测试：草稿保护、提交目标绑定、上下文模型匹配。

隔离协议测试覆盖官方 app-server 与模拟提供商，不等同于用户登录后的桌面端端到端操作，也不调用付费推理服务。

实际桌面只读诊断确认：富文本编辑器内部 DOM 不挂 React fiber，需要先沿 DOM 找最近宿主；当前窗口宿主到根有 201 层，祖先扫描上限设为 512 并保留循环检测。修复后同一真实窗口返回 `serviceTierKnown: true`、`serviceTier: default`。隔离回归同时覆盖此结构下 Fast 与标准读取；未在用户会话中主动切换速度。

分支创建期间仅禁止重复写入，当前会话参数继续轮询。创建成功立即持久化窗口配置，避免后续读取或导航失败丢失记录；桥接仅返回 fork 的配置元数据，不再重复序列化完整历史。导航交给普通轮询确认，不持有写入锁等待页面挂载。星号窗口为已配置值，实际窗口仍需新分支后续用量上报；缺少成功响应的旧分支不会被猜测为已配置。

创建请求显式设置 `excludeTurns: true`，让 app-server 跳过完整历史的响应展开（协议对分页历史已弃用此展开方式）。该字段仅影响返回内容，分支仍继承原历史。实际分支记录可用 `forked_from_id` 和 `forked_from_ordinal_exclusive` 引用原记录，分支本地没有重复消息不代表丢失上下文。

## 当前模型目录下的窗口档位核对

2026-09-08 只读核对本机 Codex 模型目录：`gpt-5.6-sol` 的 `max_context_window` 为 872000，`effective_context_window_percent` 为 95。真实分支日志上报 828400，与该限制一致。使用相同模型目录、临时配置和本地模拟提供商执行四档分支下一轮测试，结果如下：

| 请求配置 | 有效窗口上报 |
| --- | --- |
| 258000 | 245100 |
| 512000 | 486400 |
| 1000000 | 828400 |
| 1050000 | 828400 |

这组结果符合 `min(请求配置, max_context_window) * effective_context_window_percent / 100`。菜单档位是请求配置值；不是剩余容量，也不能保证突破当前模型目录上限。该上限属于本次安装及模型目录的观测结果，不应硬编码为所有模型或后续版本的固定限制。

复现命令：`python3 scripts/test_desktop_thread_protocol.py /path/to/codex /path/to/models_cache.json`。测试只读取模型目录，并复制到临时配置目录；不读取用户凭据，不连接付费推理服务。

菜单和创建分支确认框明确区分请求配置值、预计有效值与实际上报值。预计值动态读取本机 `models_cache.json` 对应模型的上限和有效比例；超过上限的档位标注“受模型上限限制”。目录缺失、字段无效或模型未知时显示“有效值待上报”。档位勾选按已知的请求配置匹配，不再拿有效窗口与配置值直接比较。自定义输入也说明其含义是请求配置。
